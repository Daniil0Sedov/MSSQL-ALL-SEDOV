# Отчёт Выявление и устранение медленных запросов с помощью SQL Server Profiler

## Цель работы

Научиться выполнять трассировку в SQL Server Profiler, выявлять медленные запросы, анализировать планы выполнения и проверять результат оптимизации.

## Описание базы данных

### SQL-код

Код создания базы, таблиц и тестовых данных: [01_setup_trainingdb.sql](01_setup_trainingdb.sql).

Создана база TrainingDB с таблицами Departments, Employees, Projects и Timesheets. В таблицы добавлены 5 отделов, 500 сотрудников, 3 проекта и 2000 записей табеля.

## Настройки трассировки

В SQL Server Profiler создана трассировка TrainingDB_Profiler_2019 по шаблону Blank. Использовались события RPC:Completed, SQL:BatchCompleted, ShowplanStatisticsProfile, ShowplanXMLStatisticsProfile и Lock:Acquired. Оставлены столбцы TextData, Duration, Reads и CPU. Установлены фильтры DatabaseName Like TrainingDB и Duration >= 100 мс.

## Проблемные запросы до оптимизации

### SQL-код

Код запросов A, B и C: [02_workload_before.sql](02_workload_before.sql).

Запрос A фильтрует Employees по Salary. Запрос B объединяет четыре таблицы. Запрос C вычисляет среднюю зарплату и число сотрудников по отделам.

## Анализ планов выполнения

До оптимизации в плане запроса A обнаружено сканирование индекса таблицы Employees: отдельный индекс по Salary отсутствует. В плане запроса B обнаружены сканирование индекса и Hash Match. В плане запроса C обнаружены сканирование индекса и Sort. Эти операции увеличивают количество обрабатываемых строк при фильтрации, соединении и сортировке.
## Меры оптимизации

### SQL-код

```sql
CREATE INDEX IX_Employees_Salary ON dbo.Employees(Salary);
CREATE INDEX IX_Timesheets_WorkDate ON dbo.Timesheets(WorkDate);
```

Полный запускаемый код: [03_create_indexes.sql](03_create_indexes.sql).

Индекс IX_Employees_Salary ускоряет фильтрацию по Salary в запросе A. Индекс IX_Timesheets_WorkDate ускоряет отбор строк по диапазону дат в запросе B.

### Краткое пояснение

После создания индексов трассировка запускается с теми же событиями и фильтрами. Полученные значения сравниваются с результатами до оптимизации.

| Запрос | Duration до, мс | Duration после, мс | Reads до | Reads после | Изменение плана |
| --- | --- | --- | --- | --- | --- |
| A | 45,643 | 47,291 | 42,67 | 50,67 | Значимых изменений не выявлено |
| B | 251,833 | 231,229 | 157,33 | 35,67 | Число чтений существенно сократилось |
| C | 306,322 | 307,187 | 57,33 | 45,00 | Число чтений сократилось; время почти не изменилось |

![Скриншот](Pasted%20image%2020261026102815.png)
## Вывод

SQL Server Profiler позволяет найти длительные запросы по показателям Duration, Reads и CPU. Наиболее заметный эффект показал индекс IX_Timesheets_WorkDate для запроса B: среднее число логических чтений уменьшилось с 157,33 до 35,67, а среднее время снизилось с 251,833 до 231,229 мс. Для запросов A и C на небольшом наборе данных время почти не изменилось, что показывает необходимость проверять эффект оптимизации измерениями, а не предполагать его заранее.
